How to run it

About five minutes to set up, then one command per session. The film How to run it shows every step below on screen.

What you need

  • Linux desktop. Built and tested on GNOME on Wayland. The game runs inside XWayland there, which is what makes screenshots and clicks possible. A plain X11 desktop should work the same way, but it hasn't been tested.
  • Steam with Dominion (app 1131620) running through Proton. Steam turns Proton on by itself for this game. Snap, native and Flatpak installs of Steam are all looked for.
  • Python 3.10+ and git. No graphics card, no root rights, no system packages: everything installs into one folder.
  • Only against the built-in computer opponents. Never run a bot against people online.

1. Install

git clone --recurse-submodules https://github.com/JCA374/dominion-steam-autopilot
cd dominion-steam-autopilot
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

The submodule dominion-v1/ is the genetic-algorithm project. It holds the evolved strategy (best_model/strategy.json) and the game engine whose buy code the autopilot calls. The five packages are python-xlib (screenshots and clicks), numpy, opencv-python-headless, pillow and rapidocr-onnxruntime (the text reader, which ships its own small models, so nothing else downloads later).

Already cloned without --recurse-submodules? Run git submodule update --init.

2. Start a game

  1. Start Dominion from Steam.
  2. From the game's own menu, start a game against the computer. Any computer opponent works.
  3. Leave the window at its normal size (927 × 1048 here) and in plain view. Clicks go to screen positions, so a window lying on top of the game would get them instead.

3. Run

.venv/bin/python autopilot/pilot.py

Keep your hand off the mouse while it plays: it moves the real pointer. Stop it at any time with Ctrl+C. It stops by itself on the score screen.

What the log means

This is real output from a recorded game:

prompt: Play Treasure cards.
  click button 'Play Treasures' @ (849,776)
prompt: Buy a card.
  $3 1 buy(s), provinces 8 -> buy ['Silver']
  click buy Silver @ (157,138)
prompt: Play Treasure cards.
=== turn 2 (early) provinces 8 deck 11
  ...
  hand ['Smithy', 'Copper', 'Copper', 'Copper', 'Silver'] actions 1 -> Smithy
  click Smithy @ (213,959)
LineMeaning
game seed … vs …Read from the game's save file: the seed names this game's memory file; the opponent's name.
kingdom:The ten kingdom cards, also from the save file.
never learnedKingdom cards outside the 15 the strategy was evolved with. It never buys them.
prompt:The sentence under the supply that says what the game wants now.
=== turn N (phase)A new turn: the strategy's phase (early, mid, late), Provinces left, cards owned.
hand […] actions N -> XWhat it read in your hand, the actions counter, and the card it chose to play.
$C B buy(s) … -> buy […]Coins and buys read from the counters, and the purchases the strategy's own code chose.
click … @ (x,y)A click, in window pixels.

Options

OptionWhat it does
--games NPlay N games in a row. After each score screen it presses Rematch and waits for the new game's save file.
--turn NYou start it in the middle of a game on turn N (and it has no memory file for this game yet).
--dryRead and decide, but never click. A safe first test: watch the log while you play yourself.
--record DIRAlso save window frames (4 per second) and every read, decision and click to DIR/. The films on this site were built from such recordings.
--model FILEPlay a different strategy file (default dominion-v1/best_model/strategy.json).
--onceHandle one prompt and exit (debugging).
--poll S, --delay SSeconds between screen reads (0.5) and after each click (0.8).

When it gets stuck

  • A prompt it doesn't understand (for example a choice from a card it doesn't know): it saves a screenshot to autopilot/unknown/, prints a line starting don't know how to handle prompt and waits. Answer the question yourself in the game; it carries on by itself.
  • Stopped mid-game? Its memory (turn, Provinces left, cards owned, empty piles) is saved after every turn in autopilot/run_<seed>.json. Start it again and it picks up where it was.

Troubleshooting

SymptomLikely cause and fix
Dominion window not foundThe game isn't running, or the window has another title. Start the game first.
Finds the window, never clicksThe prompt line under the supply isn't visible or readable: is a menu or dialog open?
Clicks the wrong placesThe window was resized or moved half off screen. Put it back to its normal size.
Clicks land in another programAnother window covers the game. Keep the game in plain view.
Very slowSomething else is using the processor: the text reader is CPU-only. See the timings on How it works.
Keeps "buying" without effectAn empty pile. Since the fix described in Lessons it notices this after one click and plans again.
