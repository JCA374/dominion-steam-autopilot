The setup: engine, models, kingdoms

Three projects work together. The engine is the game. A trainer turns the engine into models. The autopilot picks a model for the kingdom Steam dealt and plays it on the real game. This page explains each piece, and where to look when you want to change something. Updated 14 November 2026.

A new kind of model, for example a neural network, gets its own folder next to the GA: trainers/nn-v1/, with the engine as a submodule and the same protocol. The rules are never copied into a trainer. The engine, GA trainer and autopilot are separate repositories.

1 · The engine

Until 14 November the GA trained on its own small simulator, and that simulator played a slightly different game from Steam. The engine is that game rebuilt to Steam's rules, in its own repository, so every future model trains on the real thing.

Every choice in the game (play an action, buy, what to trash, what to discard to a Militia…) is one decision with a list of options. Any player answers decisions: a scripted bot, the evolved genome, a person in the GUI, or later a neural network. The Python and C engines ask the same decisions in the same order with the same shuffles, and a test plays 1,500 random games in both and compares every decision: zero differences.

2 · Models

A model is a folder. For the GA it holds the evolved strategy.json (buy lists per phase, action order, Chapel and Throne Room choices) and model.json (name, the kingdom it was trained on, date). Two more files are measured, not trained:

  • Key cards: the kingdom cards the model is built around (it buys them and wins more with them).
  • bench.json: its strength against three fixed opponents (Big Money, Smithy–Big Money, Witch–Big Money) on 200 random Steam-like kingdoms. Re-measured on 14 November with the Steam-rules engine.

best_model/ changes every training run. Only a released model (models/<name>/) is played on Steam, and it never changes after release.

3 · Kingdoms

A Steam game deals 10 of the 26 base-set kingdom cards. Three things to know:

  • How the autopilot learns the kingdom. It isn't read from the screen. Dominion saves every game as XML in its Proton folder, and the newest file lists the ten cards.
  • How a kingdom gets chosen. In the control panel you pick Random (Steam deals), a list of cards, or Auto: the training kingdom of the best model, so the model plays the cards it knows. The campaign types each name into the game's Specify Card box.
  • What a model does with cards it never learned. Nothing. A model only buys cards on its own buy lists, which come from its training kingdom. The rest are logged as untrained. In the Steam campaign, about 6 of the 10 cards in a typical game were invisible to k1-steam.

The engine knows all 26 cards now, so new models can learn any of them. One safety rule: for nine of the new cards (Artisan, Cellar, Harbinger, Library, Poacher, Remodel, Sentry, Vassal, Workshop) the autopilot can't yet answer the question Steam asks when you play them. Models are never told to buy those nine until that is built.

4 · Picking a model for a kingdom

With --model auto (the default) the selector ranks every released model after the deal:

  1. a portfolio model (portfolio-v1): it plays every kingdom. It tries all its specialists on the dealt kingdom in the engine (under a second) and the best one plays the game. See the training log;
  2. a model trained on exactly this kingdom;
  3. else a model whose key cards are all in the kingdom, highest benchmark score first;
  4. else the model with the most key cards dealt.

Plain Big Money and retired models are never chosen. Models are plug-ins: drop a folder into models/, run the benchmark, and the selector, the control panel and the pilot see it without code changes.

5 · One decision, end to end

  1. The autopilot takes a screenshot and reads the prompt (Buy a card.), the counters ($6, 1 buy) and the Province count.
  2. It sends the model a small JSON question: turn, Provinces left, kingdom, empty piles, cards owned, hand, coins.
  3. The model's policy rebuilds that position as an engine game and asks its agent the engine's own BUY decision: the same code that played it in training.
  4. The answer comes back (["Gold"]), and the autopilot clicks the Gold pile, then checks that coins went down.
