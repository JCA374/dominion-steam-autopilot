Lessons

Everything that went wrong on the way, in the order it happened, and what fixed it. Each bug was found by watching a real game, not by guessing.

1. The game ignores instant clicks

Seen: the first click (on Play Treasures) worked, the click on the Silver pile did nothing. Cause: the game only takes a click after the pointer has hovered on the target. A pointer that jumps there and presses within 80 ms isn't seen as hovering. Fix: glide the last few pixels, rest 0.35 s, press, hold 0.15 s.

2. Clicks during animations are lost

Seen: Smithy needed two or three clicks at the start of some turns. The actions counter still showed 0, and the opponent's Vassal was still in the middle of the screen. Cause: the turn was still starting up. Fix: act only on a still screen (two screenshots 0.35 s apart that barely differ), and in the action phase only once the actions counter shows at least 1. After this, Smithy played on the first click.

3. Click the card body, not its name

Seen: clicks aimed at the card-name banner sometimes missed. Cause: a hovered hand card lifts up, so the banner moves away from the pointer. Fix: click 55 px below the banner.

4. The tilted card is read upside down

Seen: on two turns of the first recorded game the log said hand ['Copper', 'Copper', 'Estate', 'Estate'] -> no action with only $2 to spend, although the game was asking for actions. Cause: the leftmost hand card is tilted, and the OCR's orientation check sometimes decided it was upside down and turned it: SMITHY came out as AHLIWS, which is exactly what the reader gives for that banner turned 180°. First fix, wrong: re-read an unmatched word turned 180°. It passed a test where I had flipped the patch myself, but on the real frame it made things worse, and in the next game Smithy was skipped again on turn 6. Lesson inside the lesson: test a fix on the real failing frame, not on a fake of it. Real fix: the orientation check is off for the hand (cards are never upside down). A word that still matches nothing is read once more on its own, and if the game asks for actions but no action card was read, it reads again before ending the phase.

5. Empty piles stalled a game for 27 turns

Seen: Provinces stayed at 2 from turn 25 to turn 52, and every turn "bought" a Duchy or an Estate. Cause: both piles were empty (a red X on the pile). The stand-in supply always had 10 of each card, so the strategy kept asking for them. Clicking an empty pile does nothing, and with one buy the turn ended without a purchase. In the simulator this can't happen: it knows the pile counts. Fix: after a buy click, if coins and buys didn't change, mark the pile empty and ask the strategy again. Restarted with the fix at turn 52, it noticed both empty piles in its first two buy phases, went back to buying treasure, and won 76 to 7 (turn 66 by its own count).

6. The evolved late game has a weak spot

That long game also showed something about the strategy itself. Its late buy list ranks Silver above Gold and keeps Copper above PASS, so a long late game fills the deck with green cards and weak treasure, and $8 hands get rare. In training this rarely mattered: the simulator ends every game at turn 40. It's a property of the model, not of the autopilot, and a reason to evolve with longer games or a three-pile ending.

7. Smaller ones

  • Each game has its own save file (gamelocal_0_-1.xml, -2, …). Read the newest, not a fixed name, or a rematch plays with the previous kingdom.
  • council_room in the save file needs _ → space before it matches "Council Room".
  • The opponent's score shield is hard to read for the OCR (single digit, coloured shield). The score screen is saved as a picture instead.
  • pkill -f pilot.py from a script kills the script too, because its own command line contains those words. Kill the Python process by its exact command instead.
  • Busy processor: with all cores taken by another job, one OCR region took 6–9 s instead of a fraction of a second. The bot still plays correctly, just slowly.
